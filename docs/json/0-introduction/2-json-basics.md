# JSON 语法十分钟速通（写给零基础）

> 作者：Eve.aic。本文只讲 JSON 格式本身，是给完全没接触过 JSON 的读者准备的预备课；文中 Mindustry 示例已随炮塔教程通过验证器实机加载验证。

很多新手的第一步卡点不是 Mindustry，而是 **JSON 文件本身写不合法**——游戏直接报一堆英文错误，看不懂就弃坑了。其实 JSON 一共就六样东西，十分钟能学完。

## JSON 只有六种值

| 类型 | 长什么样 | 例子 |
| --- | --- | --- |
| 字符串 | 双引号包起来 | `"copper"` |
| 数字 | 直接写 | `15`、`2.5` |
| 布尔 | 两个关键字 | `true`、`false` |
| null | 一个关键字 | `null` |
| 数组 | 方括号，逗号分隔 | `["a", "b"]` |
| 对象 | 花括号，`"键": 值` | `{"item": "copper", "amount": 50}` |

Mindustry 的 mod 文件，归根结底就是这些值套来套去。

## 五条铁律（90% 的报错都栽在这）

1. **键必须带双引号**：`{name: "x"}` 是错的，`{"name": "x"}` 才对。
2. **字符串只能双引号**：单引号 `'copper'` 不合法。
3. **最后一个值后面不能有逗号**：`[1, 2,]` 是错的。这是最最常见的报错来源。
4. **括号要配对**：每个 `{` 对应一个 `}`，每个 `[` 对应一个 `]`。
5. **大小写敏感**：`True`、`TRUE` 都是错的，只有 `true` 合法。

## 读一个真实例子

上一篇炮塔教程里的建造成本：

```json
"requirements": [
  {"item": "copper", "amount": 50},
  {"item": "lead", "amount": 25}
]
```

拆开看：`"requirements"` 这个键对应的值是一个**数组**（方括号），数组里有两个**对象**（花括号），每个对象有 `item`（字符串）和 `amount`（数字）两个键。读懂这个结构，你就读懂了 Mindustry 90% 的 JSON。

## 报错了怎么办

游戏日志里的 JSON 报错一般都带行号，例如：

```
JsonParseException: Unexpected character ... at line 8
```

直接去第 8 行附近，对照上面五条铁律找：多半是多了逗号、少了引号、括号没合上。把文件贴给任意一个 JSON 校验网站（搜 "JSON validator"）也能立刻定位。

## HJSON 是什麼

你可能会见到 `.hjson` 文件——它是 JSON 的宽松方言，允许不写引号、允许注释、允许尾随逗号。Mindustry 的解析器同时支持两种（`mod.json` / `mod.hjson` 都行，见 1-environment 章）。但**建议新手先写标准 JSON**：报错信息更明确，抄教程示例也不容易抄串格式。
