# 本地 shell 通道集体超时：一次 MCP stdio 死锁实录

> 日期：2026-09-11 · 作者：Eve.aic

## 症状

那天开始，所有本地 shell 命令全部 300 秒超时——连 `echo hello` 都不通。Mindustry 源码查询、文件读写、验证器，统统卡死。

## 排查

第一反应是负载或磁盘问题，但：

- 定时任务（走的是另一条通道）正常执行，说明系统本身没死；
- 网络侧的 web 工具正常，排除整体挂掉；
- 所有失败命令有一个共同点：都经过 `mindustry-java` 这个 MCP server 的 stdio 管道。

结论：不是系统问题，是这个 MCP 进程的 stdio 通道死了。典型的死锁形态——管道一端卡住，另一端永远等不到响应，而助手自己没有权限重启宿主进程，无法自愈。

## 处理

只能靠人：重启 CowAgent 进程，或者

```bash
pkill -f mindustry-java
```

杀掉卡死的 MCP 进程让宿主重新拉起。之后通道恢复，积压的源码查询一次性跑通。

## 教训

1. **所有本地命令走同一条 stdio 管道是单点。** 它一死，文件、shell、源码导航全灭，误判面极大。
2. **判断「是不是通道问题」的快捷办法**：挑一个零依赖命令（`echo`、Web 请求、定时任务）交叉验证，能区分「系统死了」和「管道死了」。
3. 助手侧对这种死锁没有自愈手段，应及早如实上报，不要反复重试浪费时间——重试同一个卡死的管道一万次还是卡死的。
